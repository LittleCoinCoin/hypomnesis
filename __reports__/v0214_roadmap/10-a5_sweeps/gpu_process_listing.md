## Spec defects not fixed

1. **`gpu_processes`' two `#[allow]`s already suppress nothing on b716087.** Step 2 item 3 says "signature and attributes unchanged". Measured: swapping `#[allow(unused_variables)]` and `#[allow(clippy::missing_const_for_fn)]` on `gpu_processes` for `#[expect]` makes `cargo clippy --locked --lib --no-default-features -- -D warnings` fail with "this lint expectation is unfulfilled" on both (the default and `--all-features` sets fail the same way): `device_index` always reaches `bounds_check`, and calling the non-const `bounds_check` keeps the fn from being const. Leaving them on the new one-line wrapper keeps two vacuous attributes; copying them to `gpu_process_listing` copies two more. The CONVENTIONS rule is written for test modules, so this is library hygiene that predates the leaf. Proposed fix: Step 2 item 3 says that `gpu_process_listing` carries only the `#[allow]`s an `#[expect]` swap shows it needs (none, measured on the current body), and that `gpu_processes` keeps its signature. Whether to drop the wrapper's existing pair is the coordinator's call (it is outside this leaf's purpose).
2. **`decide_listing`'s gate breaks `cargo test --no-default-features --lib`.** Step 1 item 3 gates `process_list_denied`/`decide_listing` with `cfg(any(all(target_os = "macos", feature = "metal"), test))`, and Step 2 item 1 has `decide_listing` call `sort_by_pid`, which is gated on backend features only. With no features and `cfg(test)`, `decide_listing` compiles and `sort_by_pid` does not (E0425). Measured on b716087: `cargo test --locked --no-default-features --lib --no-run` builds (rc 0), so the leaf would break it. No CI step runs it (CI runs `cargo check --no-default-features`, not tests), so no gate catches it. Proposed fix: Step 2 item 1 adds `test` to `sort_by_pid`'s `cfg(any(…))`, or `decide_listing` sorts with `entries.sort_by_key(|e| e.pid)` inline.
3. **Prototype claims not re-measured on b716087.** Step 1 item 3 ("a prototype of the decision, signature and `row` tests: clippy … exits 0 on stable 1.99 and on 1.88") and item 5 ("the prototype of this file, which then exits 0 under both toolchains"; the scratch-crate `^LISTING ` count) were measured at 40a701e. The item 5 prototype also predates the new probe/child-assertion design (edits 16–18), so its clippy result covers a different file. Proposed fix: the implementer re-runs `cargo clippy --locked --all-targets --all-features -- -D warnings` on stable and `+1.88` with the new file (both are in the gate set anyway), and the leaf calls these prototype figures history.
4. **Pre-condition 2 paraphrases kinfo_enumeration's `S --job` gate.** GATE CONTRACT (6) asks for a quote. The current kinfo leaf's gate prints `exit 0`, `1` and `big=0`. The pre-condition says "exit 0, `grep -c '"name":"gpujob"'` on stdout is 1 and its `used_bytes` is ≥ 268435456", which agrees. Another sweeper may be editing kinfo_enumeration, so I did not rewrite it. Proposed fix: quote `prints exit 0, 1 and big=0` once the kinfo leaf settles.
