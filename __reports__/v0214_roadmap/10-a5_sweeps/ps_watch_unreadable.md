## Defects and observations left unfixed (outside this leaf, or a design question)

1. **ps_failed_devices grep gate goes stale (my leaf's Step 2 causes it).** ps_failed_devices pins `grep -c 'ps_exit_code(exit_status, rows.is_empty(), failed)' src/bin/hmn/ps.rs` 0 → 1, and PR B's review record says that `run_ps` passing `failed` to `ps_exit_code` is "pinned by grep rather than a run". This leaf's Step 2 makes the call `ps_exit_code(exit_status, rows.is_empty(), failed, notes.unreadable)`, so that count drops to 0, and nothing then pins that `run_ps` passes `failed` (or `notes.unreadable`). Proposed fix: add a static gate to this leaf, `grep -c 'ps_exit_code(exit_status, rows.is_empty(), failed, notes.unreadable)' src/bin/hmn/ps.rs`, before 0 → after 1, catches: either count dropped or swapped at the call site. part2_close should not re-run the PR B count.
2. **remedy_macos's done gate texts are stale on b716087.** They still say `remedy_text(true, "for names")`. Its first gate also claims the `-- remedy_text` filter pins `(true, "for names")`, but on b716087 neither of that filter's two tests does (A2 renamed one to `…_keeps_to_identify`). Its static gate `grep -c 'Known residual:' src/bin/hmn/ps.rs` → 1 is **0 on b716087**: added in 1b24810 and removed in 4316c80 (`git log -S'Known residual'`). The pre-condition now quotes the done text verbatim and states the amendments, but the remedy_macos leaf itself, or an A-log note, should record that the residual paragraph was dropped. The coordinator decides.
3. **kinfo_enumeration's `--job` placement.** b716087's `sandbox.sh` parses options only before PROFILE. Its loop `break`s at the first non-dash argument, so `S --job -- CMD` runs `--job` as the command (exit 127), not a usage error 64. kinfo_enumeration's Step text ("part1_close's script exits 64 on an unknown option … it goes after `PROFILE`") holds only for an option before PROFILE. Its sweeper should check this. Every `--job` gate in this leaf (g17, g22) uses the after-PROFILE form.
4. **Gates that b716087 cannot run as written.** g15 (needs `count_denied.py`), g17 and g22 (need `--job`). Their b716087 befores are recorded as what the command actually does there (missing file, exit 127) plus the hmn half where it can be isolated. Each after depends on kinfo_enumeration. No gate has before = after unless labelled `(guard)`: g21 is `exit 0`, `2`, `0` → `exit 0`, `2`, `0`, labelled guard and placed beside moving gates. No tautology found.
5. **NoGpuSource text changed since the README baseline.** The campaign README's BASELINES quote `(NVML, DXGI, PDH, and nvidia-smi all failed or are disabled)`. On a macOS release build at b716087 it reads `no GPU measurement source available (Metal, NVML, and nvidia-smi all failed or are disabled)`.
