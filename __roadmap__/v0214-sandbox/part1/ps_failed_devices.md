## Step 2: run_ps states skipped devices and fails when all failed
**Goal**: Make `run_ps` count the devices it tried and the ones that failed, print one line per skipped device, exit `2` without a table when every device failed, and exit `2` rather than `1` for an empty `--exit-status` listing that skipped a device.
**Implementation Logic**:
1. In `ps.rs::run_ps`, count `tried` (incremented right before each `gpu_processes(idx)` call, so one per entry of `device_indices` that reaches it) and `failed`. In the `match gpu_processes(idx)`, the arm `Err(e) if filters.device.is_some()` now builds its line with `device_query_failure_line(idx, &e, false)` (output byte-identical to today's `hmn: ps failed to query device {idx}: {e}`); the arm `Err(_) => continue` becomes `Err(e) => { eprintln!("{}", device_query_failure_line(idx, &e, true)); failed += 1; continue; }`.
2. After the loop and before the table or JSON is built: `if every_device_failed(tried, failed) { eprintln!("{ALL_DEVICES_FAILED_LINE}"); return ExitCode::from(2); }`. Nothing is printed to stdout, as in the `--device` failure path: a table or `[]` after "no device could be queried" would be read as "idle" by any script that checks stdout. Decision, state it in the doc: `--json` consumers get an empty stdout and exit `2`, not `[]`.
3. `--exit-status` interaction, decided (user decision U2): the final exit is `ExitCode::from(ps_exit_code(exit_status, rows.is_empty(), failed))`, replacing `if exit_status && rows.is_empty() { FAILURE } else { SUCCESS }`. Implement `ps_exit_code` as: `!exit_status || !rows_empty` → 0; otherwise `failed > 0` → 2; otherwise 1. So an all-failed listing exits `2` with or without the flag (item 2), and a listing where some device answered but nothing matched exits `2`, not `1`, with the flag when a tried device failed: `2` means "can't tell"; `1` means "queried, nothing matched"; folding the first into the second is the silent wrong answer, because the job may sit on the skipped device. Rows listed, or no flag, keep today's `0`: the rows of the devices that answered are still printed and the skip line states the gap. `ps_watch_unreadable` (PR C) extends this function by appending a fourth parameter, `relevant_denied: usize`, and adds its own tests; it does not re-create the function.
4. When no device was tried (`device_count()` failed, so `device_indices` is empty), `tried` is 0, `every_device_failed(0, 0)` is false, `failed` is 0, and the code falls through to today's empty table and exit `0` (or `1` with `--exit-status`). Do not change `device_count().unwrap_or(0)`.
5. Do not touch `gpu_processes`, the JSON shape, `summary`/`SummaryNotes` or the `re-run elevated` strings (the macOS remedy is `remedy_macos`'s; the unreadable counts and the remedy on a skip line are PR C's, which will append its remedy to a skip line when the error is `ProcessListDenied`). The names it relies on: `pub fn device_query_failure_line`, `ALL_DEVICES_FAILED_LINE`, `every_device_failed`, `ps_exit_code` (this leaf's Deliverables). `ps.rs` and `tests/cli_ps.rs` are also edited by other PR B leaves (`remedy_macos`, `spill_cell_na`) in non-adjacent places; the coordinator resolves those textual conflicts at rebase.
6. Replace the stub bodies with the real ones: `every_device_failed` is `tried > 0 && failed >= tried`; `device_query_failure_line` appends ` (skipped)` when `skipped`; `ps_exit_code` as in item 3.

Step 1's four red tests (the three unit tests and the sandbox test) all turn green in this step, and nothing else is red here. Step 1 alone is not pushable for a second reason: its stubs are unused in the non-test build, so `cargo clippy --locked --bins --all-features -- -D warnings` fails on four `is never used` errors (`ALL_DEVICES_FAILED_LINE`, `device_query_failure_line`, `every_device_failed`, `ps_exit_code`; measured on a scratch copy of the stubs), until this step's `run_ps` calls them.
