# Item 7: n/a vs ? in SPILL and PAGED cells

**Goal**: Render `n/a` in the SPILL and per-PID `PAGED` cells on Linux and macOS, where spill cannot exist, and keep `?` on Windows, where it can exist but could not be read, through one pure core that `hmn ps` and `hmn watch` share and that tests exercise on any OS.
**Pre-conditions**:
- [ ] docs_pr gate "PR A is open and CI is green" met, so R01 records the `n/a` decision and its compile-time rule
- [ ] `src/bin/hmn/format.rs`, read directly: `column_width` sizes each column as `max(header.len(), widest cell)` in bytes, and `src/bin/hmn/watch.rs` gives the `SPILL` column a minimum width of 5 (`("SPILL", 5)` in its width table), so a 3-byte `n/a` never widens a column

## Step 1: Stubs and failing tests
**Goal**: Add the cores as stubs that keep today's glyph, and change every test that pins the cell, so each fails on an assertion on non-Windows.
**Implementation Logic**:
1. In `src/bin/hmn/format.rs` add, next to `spill_cell`, `pub const fn spill_cell_for(spilling: Option<bool>, paged: Option<bool>, spill_cannot_exist: bool) -> &'static str`, `pub const fn paged_cell_for(paged: Option<bool>, spill_cannot_exist: bool) -> &'static str` and `pub const SPILL_CANNOT_EXIST: bool = !cfg!(windows);`. Stubs ignore the flag and return `?` for `None` (`paged_cell_for` returns `yes` / `no` / `?`). Docs on each (`missing_docs_in_private_items` is warned). `spill_cell` stays and now calls `spill_cell_for(spilling, paged, SPILL_CANNOT_EXIST)`; add `pub const fn paged_cell(paged: Option<bool>) -> &'static str` calling `paged_cell_for(paged, SPILL_CANNOT_EXIST)`.
2. Why a flag and not `is_spill_measurable()`: that is a runtime `PDH` probe that is `false` on pre-`WDDM 2.0` Windows and on a PDH hiccup, which are exactly the cases that keep `?`. A compile-time `!cfg!(windows)` says "this platform has no spill to measure" and nothing else. A Windows build without the `pdh` feature keeps `?` too (R01: `?` stays on Windows).
3. Tests in `format.rs` `mod tests` (replace `spill_cell_renders_the_honesty_contract`): `spill_cell_for_renders_n_a_where_spill_cannot_exist` (`(None, None, true)` gives `n/a`, `(None, None, false)` gives `?`; `(Some(true), Some(true), either)` gives `PAGED`, `(Some(true), Some(false), either)` gives `device`, `(Some(false), Some(false), either)` gives `no`); `paged_cell_for_renders_n_a_where_spill_cannot_exist` (`Some(true)` gives `yes`, `Some(false)` gives `no`, `None` gives `n/a` or `?` by flag); `spill_cell_wrapper_follows_the_compile_time_platform` with literal expectations per `cfg` (do not compute them from `SPILL_CANNOT_EXIST`, which would be circular).
4. Update the pinned tests so each states both platforms with literals, `if cfg!(windows) { "…?…" } else { "…n/a…" }` built from two explicit strings. `ps.rs`: `format_ps_table_single_row`, `format_ps_table_protected_name_renders_question_mark` and `format_ps_table_missing_name_renders_question_mark` end their expected row with `?    ` (the SPILL cell, where `row()` has `spilling: None`; the NAME `?` stays); the non-Windows expected row ends `n/a  `. `format_ps_table_spill_column_renders_paged_device_no_and_unknown`: the `d.exe` line, `?     ` becomes `n/a   ` off Windows. `watch.rs`: `format_watch_rows_text_unmeasurable_spill_renders_question_mark_not_no` asserts `s.contains('?')` and `!s.contains("no")` for a `None` spill; off Windows it asserts `s.contains("n/a")` (`n/a` contains no `no`, so the negative assertion stays). Rename it `..._renders_the_unknown_glyph_not_no`. `format_watch_per_pid_block_paged_column`: `cell("15534")` is `?` on Windows, `n/a` elsewhere. `format_watch_rows_text_missing_name_renders_question_mark` is about the NAME and stays as is.
5. Add the two alignment tests from the gates. Table alignment code needs no change: `column_width` takes `max(header.len(), widest cell)` and the SPILL and PAGED headers are 5 bytes, so `n/a` (3) never widens a column and the cell is padded like `?` was (`n/a  ` where `?    ` was). The test makes that a checked fact rather than a reading of the code. CLIPPY IN TESTS (campaign README): every new or changed test in this leaf is `assert_eq!` or `assert!` on literals, with `if cfg!(windows) { … } else { … }` choosing between two explicit strings, so there is no `panic!`, `unwrap`, `expect` or `_` arm and no `#[allow]` is needed. Measured on a scratch composite of PR B's code and tests carrying these tests: `cargo clippy --locked --all-targets -- -D warnings` for the default, `--all-features` and `--all-features --target x86_64-unknown-linux-gnu` sets, and `cargo +1.88 clippy --locked --all-targets --all-features -- -D warnings`, all exit 0.
6. Do not edit any JSON path: `format_ps_json`, `format_watch_rows_json` and `format_watch_summary_json` keep `null`.
7. Acceptance of the red: the check below runs with `--no-fail-fast 2>&1`, and its output must show `grep -c 'panicked at'` = 9 and `grep -c 'error\[E'` = 0 (measured on a scratch copy of c1810a5 with these stubs and tests: 9 and 0: the three core tests, `format_ps_table_single_row`, `..._protected_name_renders_question_mark`, `..._missing_name_renders_question_mark`, `..._spill_column_renders_paged_device_no_and_unknown`, `format_watch_rows_text_unmeasurable_spill_renders_the_unknown_glyph_not_no` and `format_watch_per_pid_block_paged_column`; the two alignment tests pass already). `format.rs`, `ps.rs` and `watch.rs` are also edited by `remedy_macos` and `ps_failed_devices` in non-adjacent places (`ps.rs` tests, the `format.rs` remedy block, the `watch.rs` hint), which the coordinator resolves at rebase.
