## Step 1: Pin the out-of-range answer and the NoGpuSource text
**Goal**: Add the tests that fail today, on an assertion and not on a missing symbol, and tighten the smoke test that accepts either error.
**Implementation Logic**:
1. No new symbol is needed, so every test below fails on an assertion at the start of this step. `bounds_check` is private and the public API is untouched.
2. `tests/macos_smoke.rs`: add `device_index_past_count_is_out_of_range_on_apple_silicon`, not `#[ignore]` (it needs only `sysctl machdep.cpu.brand_string`, which works under P). Body: `let Ok(1) = device_count() else { return; };` so an Intel Mac or a host without a count source skips (a `let … else`, not a `match` with a `_` arm: `Cargo.toml` denies `clippy::wildcard_enum_match_arm`). Inside, for `index = 1` assert `matches!(device_info(1), Err(HypomnesisError::DeviceIndexOutOfRange { index: 1, count: 1 }))`, and the same for `process_gpu_info(1)` and `gpu_processes(1)`. Use `matches!` on the fields, not on `Display`, per the `error.rs` "Display vs structured fields" contract. CLIPPY IN TESTS (campaign README): no `panic!`, `unwrap`, `expect` or `_` arm anywhere in this leaf's tests, so no `#[allow]` is needed; measured on a scratch copy of the Step 2 state with all three test edits below: `cargo clippy --locked --all-targets -- -D warnings` for the default, `--all-features` and `--all-features --target x86_64-unknown-linux-gnu` sets, `cargo +1.88 clippy --locked --all-targets --all-features -- -D warnings` and `cargo +1.88 test --locked --all-features` all exit 0 (the `error.rs` test module needs only `use super::*;`, which clippy accepts in a `#[cfg(test)]` module). ## Step 2: Metal arm, cfg-selected NoGpuSource text, docs and CHANGELOG
**Goal**: Make `bounds_check` consult Metal's count, name Metal in the macOS `NoGpuSource` text, and update every doc this makes stale.
**Implementation Logic**:
1. `src/gpu/mod.rs::bounds_check`: add, before the `nvml` arm, `#[cfg(all(target_os = "macos", feature = "metal"))] if let Some(count) = metal::device_count() { return if index >= count { Err(DeviceIndexOutOfRange { index, count }) } else { Ok(()) }; }`. Metal goes first because `device_count()` (mod.rs) tries it first, so the bound a caller is told matches the count `hmn` reports. `index >= count`, as in the two existing arms. On an Intel Mac `metal::device_count()` is `None`, the arm falls through, and the answer stays `NoGpuSource` as before. No change to `metal.rs`: `device_count` is already `pub(super)`.
2. Do not special-case a sandbox. `device_count` reads `sysctl machdep.cpu.brand_string`, which P allows (measured: `hmn ps` under P reaches `gpu_processes(0)`, so the count is 1). The out-of-range answer therefore also holds in a sandbox.
3. `src/error.rs`, `NoGpuSource`: select the text per platform with `#[cfg_attr(target_os = "macos", error("no GPU measurement source available (Metal, NVML, and nvidia-smi all failed or are disabled)"))]` and `#[cfg_attr(not(target_os = "macos"), error("no GPU measurement source available (NVML, DXGI, PDH, and nvidia-smi all failed or are disabled)"))]` (run `cargo fmt`: it wraps each attribute over several lines, which is why the static gate on `Metal, NVML, and nvidia-smi all failed` counts the message strings, not the attribute head). Decision: cfg-selected, not "list all five". Listing all five would change the Windows and Linux bytes for no reason those platforms have, and the macOS list still would not be true there. The macOS list is Metal, NVML and `nvidia-smi` because those three are compiled in and tried on macOS under the default features (`nvml::device_count` and `nvidia_smi::query` are gated by feature, not OS). The `cfg_attr` form was compiled with thiserror 2 during drafting, natively on aarch64-apple-darwin and via `cargo check --target x86_64-unknown-linux-gnu`; if it fails to compile on an older toolchain in the 1.88 MSRV job, fall back to `#[error("no GPU measurement source available ({})", NO_SOURCE_BACKENDS)]` with a `const NO_SOURCE_BACKENDS: &str = if cfg!(target_os = "macos") { … } else { … };`, which is equivalent.
4. Update the `NoGpuSource` variant doc ("Returned when `NVML`, `DXGI`, `PDH`, and `nvidia-smi` all failed…") to say `Metal` replaces `DXGI` and `PDH` on macOS. Update the enum doc at `error.rs:7-8`, which lists "Apple Metal" among *future* backends: Metal shipped in v0.2.3, so the example becomes "AMD `ROCm` SMI".
5. `# Errors` docs in `src/gpu/mod.rs`, each saying "…reported by `NVML` or `DXGI`": `device_info`, `process_gpu_info` and `gpu_processes` become "reported by `NVML`, `DXGI` or `Metal`". `bounds_check`'s own doc (it says "Tries `NVML` first; on Windows, falls back to `DXGI`") gains the macOS line. Its `#[allow(clippy::unnecessary_wraps)]` comment ("Result is necessary only when nvml or dxgi feature returns Err") adds `metal`. `device_count`'s `# Errors` is unchanged (it never returns the out-of-range error).
6. `CHANGELOG.md` `## [Unreleased]`: one bullet under `### Fixed` (add the subheading if absent; the coordinator merges duplicates at rebase): `hmn ps --device 1` on an Apple Silicon Mac now says `device index 1 out of range (have 1 devices)`, where it printed the NoGpuSource text naming four backends macOS lacks; on macOS the NoGpuSource text names Metal. Windows and Linux text unchanged. Cite F2 of the field-check report.
7. Stale artifacts not owned here: `hmn ps --help` says an unlistable `--device` exits 2, which stays true, so no CLI help changes. The README and FAQ never quote the NoGpuSource text, as grep confirmed.
8. Squash group (U3): Steps 1 and 2 push as one commit. Step 1's two tests turn green in Step 2 and nothing else is red there, so the squashed commit carries Step 2's message and passes the gate set. Step 1 alone is a red commit and is never pushed.
**Deliverables**: `src/gpu/mod.rs` (`bounds_check` Metal arm; `# Errors` docs of `device_info`, `process_gpu_info`, `gpu_processes`; `bounds_check` doc); `src/error.rs` (`HypomnesisError::NoGpuSource` cfg-selected `#[error]` text and doc; enum doc without "Apple Metal"); `CHANGELOG.md` (`[Unreleased]` `### Fixed` bullet)
