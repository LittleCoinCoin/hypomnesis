## Step 2: Implement the dispatcher, the decision and the variant
**Goal**: Make `gpu_process_listing` the one dispatcher, `gpu_processes` its wrapper, and `ProcessListDenied` the answer to an enumerated but unreadable list.
**Implementation Logic**:
1. `src/gpu/mod.rs::process_list_denied(others_read, denied)`: `Some(denied)` only when `others_read == 0 && denied > 0`, with the count as `u32::try_from(denied).unwrap_or(u32::MAX)`; otherwise `None`. A zero-balance read counts as read (it is in `others_read`), so profile S, where the sandbox's own processes are readable, is `Ok`. Nothing denied is `Ok(empty)`: an idle machine is not an error. `decide_listing(entries, denied_pids, others_read)`: `process_list_denied(others_read, denied_pids.len())` returns `Err(HypomnesisError::ProcessListDenied { denied })` on `Some`, which drops the caller's own row (a sandboxed caller's own row is not returned on its own, and the doc says so: hmn lists itself at 16 KiB, so under profiles P and S0 `entries` is exactly `[the caller's row]` with `others_read` 0, and returning it as `Ok` would be the silent zero again); otherwise it sorts `entries` with `sort_by_pid` and returns `Ok(GpuProcessListing { entries, denied_pids })`. `sort_by_pid` is gated on the backend features only (`src/gpu/mod.rs` ~557, measured on b716087), while `decide_listing` is gated `cfg(any(all(target_os = "macos", feature = "metal"), test))`, so add `test` to `sort_by_pid`'s `cfg(any(…))`; otherwise `cargo test --locked --no-default-features --lib` fails with E0425 (amendment A5).

## Step 3: Document the API, the per-platform table and the CHANGELOG entry
**Goal**: State the new API in rustdoc with the weight on the count, and update every doc line the change made stale.
**Implementation Logic**:
1. `gpu_process_listing` rustdoc in `src/gpu/mod.rs`: what the listing is; a per-platform table of `denied_pids` and `ProcessListDenied`: Linux, always empty and never returned; Windows, always empty and never returned (PDH and NVML return every process's VRAM from one system-wide query, so only names can be refused, which `[protected]` already states); macOS, the PIDs whose ledger read the caller's sandbox refused (`EPERM`), the caller's own PID and gone PIDs excluded, and `ProcessListDenied { denied }` when the list was enumerated but no process other than the caller's could be read, zero balances counting as read, and the caller's own row not returned in that case.
