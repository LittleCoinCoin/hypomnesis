## Step 1: Stub the remedy, rewire the callers, and write the failing tests
**Goal**: Add the remedy selection with a stub that keeps the Windows text, rewire `format_ps_summary` and the growth hint through it, and add the tests that fail on assertions.
**Implementation Logic**:
1. `src/bin/hmn/format.rs`, after `spill_cell`: `pub const REMEDY_OUTSIDE_SANDBOX: bool = cfg!(target_os = "macos");` (the one platform selection; it is a `bool` because PR C passes it on) and `pub fn remedy_text(outside_sandbox: bool, elevated_purpose: &str) -> String`. Stub body: `let _ = outside_sandbox; format!("re-run elevated {elevated_purpose}")`, which compiles without a warning and fails every `true` assertion. Doc comments on both (`missing_docs_in_private_items` is warned): the const says why the selection is compile time (a sandbox is the only thing that withholds a process on macOS, and `sudo` does not lift it); `remedy_text` says it is pure, so the macOS text is tested on any OS the way `spill_cell`'s core is. These names and this signature are the contract `ps_watch_unreadable` extends: it calls `remedy_text` directly, with the purpose `"for names"` for the denial text and the `N unreadable` clause, and creates none of these (no wrapper, no second constant). That makes the macOS result of `remedy_text(true, "for names")` a seam between PR B and PR C: it must be exactly the bare `re-run outside the sandbox`, which Step 1 item 5's seam test pins and Step 2 item 1's rustdoc states.
